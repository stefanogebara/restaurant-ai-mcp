## REAL ISSUES FOUND

### HIGH — 1
**H1 — "Salvar e Sair" in onboarding wizard redirects to English landing page**
Click flow: /onboarding → click "Salvar e Sair" (top-right) → lands on / in EN
Expected: lands on /host-dashboard/simple
Impact: Brazilian owner mid-onboarding hits an English marketing page with no clear way back to their dashboard.

### MEDIUM — 3
**M1 — Survey question save calls wrong API endpoint**
WhatsApp settings page → "Pergunta da pesquisa" field → save button POSTs to /api/manager-preferences (returns 200), but the field reads from /api/surveys?action=config. Edit is silently lost on reload.

**M2 — /subscription/manage missing Stripe Customer Portal button**
Users can switch plans but cannot update payment methods, download invoices, or self-cancel via Stripe's hosted portal. Backend get-subscription.js exposes hasBillingPortal: true but frontend doesn't render the button.

**M3 — Tables page status label "Available" hardcoded English**
In an otherwise PT-BR UI. Should be "Disponível".

### LOW — 2
**L1 — /api/subscription/status returns 404**
Catch-all rewrite (/api/(.*) → /api/api-not-found) swallows it. Actual file is /api/subscription-status (no rewrite for slashed path). Frontend works because it calls /api/get-subscription directly.

**L2 — Tables "Delete" action is actually "Desativar" (soft delete)**
UX clarification needed — users may expect hard delete.

- ManagerAIUsageBar invisible at low utilization (<80%). Worth confirming the threshold is intentional.
